# Market Field preliminary evaluation

This directory is a versioned engineering and descriptive-empirical audit of the repository's Market Field implementation. It is suitable as preliminary evidence for a paper appendix, but it does **not** evaluate forecast skill, trading performance, statistical discovery, or economic value.

## Reproduce

From the repository root, using the repository virtual environment:

```powershell
.\.venv\Scripts\python.exe docs\papers\market-field\supplement\evaluate_market_field.py
.\.venv\Scripts\python.exe docs\papers\market-field\supplement\build_notebook.py
```

The default evaluation uses a locally retained snapshot and does not contact Yahoo. Raw Yahoo CSVs are intentionally excluded from Git and are not redistributed with the repository. Therefore this command reproduces the recorded run only on a machine that retains the files whose hashes appear in the manifest; it is not a fresh-clone offline reproduction.

If the local files are absent, the harness fails with an explicit message. To create a new snapshot intentionally:

```powershell
.\.venv\Scripts\python.exe docs\papers\market-field\supplement\evaluate_market_field.py --force-fetch
```

`data/raw/manifest.json` records the observation time, provider, package versions, repository context at data capture, completion policy, per-file SHA-256 hashes, and exclusions. It is the frozen input manifest and is not rewritten by an ordinary evaluation run. Re-fetching changes the experiment, will not reproduce the recorded hashes, and should receive a new snapshot/version label before being compared with this run.

Every evaluation writes `results/run_receipt.json` after the tables and figures. The receipt records UTC start/completion times, the current Git HEAD and porcelain status, an explicit dirty-tree flag, per-file hashes for the evaluated implementation and harness, runtime dependency versions, the frozen-manifest hash, and hashes for every result/figure generated by the harness. The receipt deliberately excludes its own hash to avoid a circular digest. When the tree is dirty, HEAD is only a repository reference: the receipt's source-file hashes, not the commit alone, identify the evaluated working-tree code.

## Contents

- `evaluate_market_field.py`: deterministic evaluation harness and figure generator.
- `market_field_preliminary.ipynb`: executed, top-to-bottom notebook companion.
- `PRELIMINARY_EVALUATION.md`: result narrative, claim boundaries, and paper-ready table/figure plan.
- `data/raw/`: local-only completed-bar OHLCV files plus the tracked hash manifest; CSVs are not redistributed.
- `results/`: machine-readable diagnostics covering unrounded prefix invariance, history and entropy sensitivity, maturity contracts, semantic anchors, latency, state sequence, shadow-boundary audit, the evaluation run receipt, and the separate live endpoint probe.
- `figures/`: five paper-oriented diagnostic figures.
- `probe_live_endpoint.py`: operational probe of the deployed endpoint; this is not part of the frozen empirical experiment.

## Dependency snapshot

The recorded environment versions live in `results/run_receipt.json`, alongside the hashes of the imported implementation files. The implementation itself is imported from `backend/app/services`; because an evaluation may be run from a dirty working tree, the receipt's per-file hashes are the authoritative link to the code evaluated. The frozen data manifest remains authoritative for the locally retained OHLCV inputs.

## Interpretation guardrail

The evaluation supports statements about tested prefix behavior, repeatability, initialization and parameter sensitivity, descriptive cross-timeframe behavior, formula anchors, lexicon calibration diagnostics, and the option integration's zero algorithmic authority. It cannot support a claim that any state forecasts returns or that the system improves an options strategy.
